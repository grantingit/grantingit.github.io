通信方式

基础概念

  • GPIO：General Purpose Input/Output，通用输入输出引脚。可以读高低电平、输出高低电平、做外部中断，也可以被复用成 UART、I2C、SPI 等通信引脚。它本身不是通信协议。

  • 串行 vs 并行：串行一位一位传，线少、距离远；并行多位同时传，线多、速度快但距离短。单片机通信大多用串行。

  • 同步 vs 异步：同步有单独时钟线，如 I2C、SPI；异步没有时钟线，靠双方约定波特率，如 UART。

  • 单工/半双工/全双工：只能单向叫单工；能双向但不能同时叫半双工；能同时收发叫全双工。

  • 主从：主机产生时钟或发起通信，从机响应。I2C、SPI 通常是主从结构。

  • 波特率：通信速率，UART 双方必须一致，常见 9600、115200。

  • 电平：TTL/CMOS 常见 3.3V、5V；RS232 是负逻辑高压；RS485/CAN 是差分信号。电平不匹配会烧引脚。

  • 概念 层次 作用 和通信的关系
    GPIO 硬件接口 通用输入输出引脚 物理层基础，可复用成 UART/I2C/SPI
    引脚复用 Pin Mux / AF 硬件配置 把 GPIO 切换成外设功能 GPIO 和外设之间的桥梁
    外设 Peripheral 硬件模块 芯片内部实现 UART、I2C、SPI 等 通信协议的硬件实现
    寄存器 Register 硬件编程接口 配置方向、波特率、中断等 软件通过寄存器控制硬件
    时钟 Clock / RCC 硬件资源 给外设提供工作时钟 没时钟，UART、SPI 都不工作
    中断 Interrupt / EXTI / NVIC 硬件机制 事件通知 CPU 收发数据、引脚变化触发
    DMA 硬件机制 不占 CPU 搬数据 UART/SPI/I2C 批量传输常用
    定时器 Timer 硬件外设 计时、PWM、输入捕获 可做波特率、超时、协议时序
    ADC / DAC 模拟外设 模拟与数字转换 不是通信，但常和单片机外设一起用
    看门狗 WDT 硬件外设 程序跑飞复位 可靠性相关
    总线 AHB / APB 硬件结构 CPU 和外设之间的通道 外设挂载在总线上
    存储器映射 Memory Map 硬件结构 外设寄存器映射到地址 访问寄存器就像访问内存
    位带 Bit-band 硬件特性 原子操作某一位 常用于 GPIO 原子控制
    电源管理 / 复位 硬件资源 低功耗、复位控制 影响外设工作状态

1. GPIO

通用引脚。可配置为输入、输出、上拉、下拉、开漏、推挽、中断、复用功能等。通信中常用来做片选 CS、复位、使能、中断通知，也可以软件模拟 I2C/SPI/UART，叫 bit-banging，但占 CPU。

2. UART / USART

最常用的异步串行通信。一般三根线：TX、RX、GND。点对点，全双工。数据格式通常是：起始位 + 数据位 + 校验位 + 停止位。
UART 是协议，TTL、RS232、RS485 是不同电气层：

  • TTL UART：板内短距离，3.3V/5V。
  • RS232：点对点，抗干扰一般，距离约十几米。
  • RS485：差分，抗干扰强，可多点，距离可达上千米，常配 UART 使用。

3. I2C

两线：SDA 数据、SCL 时钟。同步、半双工、主从、多设备共享总线。每个从机有地址，常用 7 位地址。SDA/SCL 是开漏，必须接上拉电阻。速度常见 100k、400k、1M、3.4M。适合连接传感器、EEPROM、小屏等低速外设。

4. SPI

四线：SCK 时钟、MOSI 主发从收、MISO 主收从发、CS 片选。同步、全双工、高速。没有地址，靠 CS 选中不同从机。速度可到几 MHz 到几十 MHz。适合 Flash、屏幕、高速 ADC 等。

5. CAN

差分总线：CAN_H、CAN_L，需要收发器。多主、总线型、抗干扰强，常用于汽车和工业。消息靠 ID 仲裁，不是地址。速度常见 125k、250k、500k、1M。

6. 其他

  • 1-Wire：单线加地，如 DS18B20 温度传感器。
  • USB：复杂，主机/设备结构，差分信号，热插拔。
  • 无线：蓝牙、WiFi、LoRa 等，属于另一类，不展开。

三、简单对比

接口 线数 同步 双工 特点
UART TX/RX/GND 异步 全双工 简单，点对点
I2C SDA/SCL 同步 半双工 两线多设备，地址寻址
SPI SCK/MOSI/MISO/CS 同步 全双工 高速，片选
CAN CAN_H/CAN_L 异步 半双工/多主 抗干扰，汽车工业
RS485 A/B 配 UART 半双工常见 长距离多点

注意点

通信不只看接口，还要注意：共地、电平匹配、上拉电阻、终端电阻、线长、干扰、波特率一致、中断/DMA/缓冲区、帧协议和校验。实际项目中，UART/I2C/SPI 只是底层，上面还要定义“帧头、长度、命令、数据、校验、帧尾”等协议。

通信外设/协议类，和 UART 类似

这些是“外设 + 协议”：

  • I2C：两线，SDA/SCL，半双工，多从机地址寻址。
  • SPI：四线，SCK/MOSI/MISO/CS，全双工，高速。
  • CAN：差分，多主，汽车工业常用。
  • USB：复杂主机/设备结构。
  • I2S：音频通信。
  • SDIO：SD 卡、WiFi 模块等。
  • Ethernet：以太网。
  • 1-Wire：单线，如 DS18B20。

电气层概念，和 UART 搭配出现

UART 是协议，但电气层可以不同：

  • TTL UART：3.3V/5V，板内短距离。
  • RS232：负逻辑，点对点，十几米。
  • RS485：差分，抗干扰，多点，上千米。
  • 差分信号：CAN、RS485、USB 都用。
  • 共地、电平转换、上拉电阻、终端电阻、隔离：物理层细节。

软件抽象层概念

这些不是硬件，但常一起出现：

  • HAL / LL / BSP：硬件抽象层、底层驱动、板级支持包。
  • 轮询 / 中断 / DMA：三种数据搬运方式。
  • FIFO / 环形缓冲区：串口收发缓存。
  • RTOS：任务调度，通信常在任务里处理。
  • 协议帧：帧头、长度、命令、数据、校验、帧尾。

ST-Link VS TTL

对比项 TTL 转 USB 模块 ST-Link
电脑侧 USB USB
目标侧 TTL UART SWD / JTAG
目标侧协议 异步串行：TX/RX、波特率 同步串行调试协议：SWCLK/SWDIO 或 JTAG
主要用途 串口通信、打印、AT 指令 下载程序、调试、断点、读寄存器/Flash
电脑上表现 虚拟 COM 口 调试器设备；有的还带虚拟 COM 口
能否烧录 一般不能，除非走 Bootloader 可以烧录、调试
典型芯片/固件 CH340、CP2102、FT232 ST-Link 内部 MCU + 固件
连接线 TX、RX、GND SWDIO、SWCLK、GND、RST、3.3V 参考

ST-Link 的原理

ST-Link 内部本身也是一个小单片机，运行专用固件。它接收电脑通过 USB 发来的调试命令，然后转换成目标 MCU 能识别的 SWD 或 JTAG 时序。

以 SWD 为例：

  • 电脑 USB → ST-Link
  • ST-Link 转换成 SWD 信号
  • SWD 接到 STM32 的 SWDIO、SWCLK
  • ST-Link 通过 ARM CoreSight 调试接口访问 CPU 内核、内存、Flash

所以它可以做到：

  • 下载程序到 Flash
  • 单步调试
  • 打断点
  • 查看变量、寄存器
  • 复位目标芯片

这些都不是 UART 能直接做的。

那 ST-Link 和 UART 完全没关系吗？

也不是。很多 ST-Link 还带一个 虚拟串口 VCP 功能。

这部分可以理解为：

  • ST-Link 的调试部分：USB 转 SWD/JTAG
  • ST-Link 的串口部分：USB 转 TTL UART

如果你把目标 MCU 的 UART TX/RX 接到 ST-Link 对应的 RX/TX 引脚，电脑上就会出现一个虚拟 COM 口。
这时这个串口功能，和 CH340 那种 TTL 转 USB 是类似的。

关键区别

  • TTL 转 USB：电脑 USB ↔ TTL UART，主要用来串口通信。
  • ST-Link：电脑 USB ↔ SWD/JTAG，主要用来调试和烧录。
  • ST-Link 附带的虚拟串口：电脑 USB ↔ TTL UART，这部分才和 TTL 转 USB 类似。
  • UART 是异步串行，没有时钟线，双方约定波特率。
  • SWD 是同步串行，有时钟线 SWCLK，由 ST-Link 驱动。

一句话总结：

ST-Link 也是 USB 桥接器，但它桥接的是 USB 到 SWD/JTAG 调试接口；TTL 转 USB 桥接的是 USB 到 UART。两者原理相似，目标协议和用途不同。ST-Link 自带的虚拟串口功能，才和 TTL 转 USB 类似。
